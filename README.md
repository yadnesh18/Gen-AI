# qa-inference-service

Stateless Spring Boot microservice that accepts a fully-composed prompt (RAG already
done upstream) and returns an answer generated by a Gemma model hosted on Google AI Studio.

**Out of scope**: retrieval, embeddings, vector search, document chunking. This service
only does inference.

---

## Tech Stack

| Component | Technology |
|---|---|
| Language | Java 17 |
| Framework | Spring Boot 3.5.4 |
| Build Tool | Maven |
| AI Framework | Spring AI 1.1.6 (`spring-ai-starter-model-google-genai`) |
| LLM | Google AI Studio (Gemma, via the Google GenAI API) |
| Logging | SLF4J + Logback |
| Validation | Jakarta Validation |
| API Docs | springdoc-openapi (Swagger UI) |
| Testing | JUnit 5 + Mockito |

## Step-by-step: Building this in IntelliJ IDEA

### 1. Get a Google AI Studio API key
1. Go to https://aistudio.google.com/apikey
2. Sign in with a Google account (no billing needed for the free tier).
3. Click **Create API key**, copy it somewhere safe. **Do not paste it into any file you'll commit.**

### 2. Open the project in IntelliJ
1. `File > Open` and select the `qa-inference-service` folder (the one containing `pom.xml`).
2. IntelliJ will detect it as a Maven project and start importing dependencies automatically.
   If prompted, choose **"Load Maven project automatically."**
3. Wait for the Maven import to finish (progress bar bottom-right). This downloads Spring Boot,
   Spring AI, Lombok, springdoc, etc. from Maven Central / repo.spring.io.

### 3. Enable annotation processing for Lombok
1. `Settings/Preferences > Build, Execution, Deployment > Compiler > Annotation Processors`
2. Check **"Enable annotation processing."**
3. If IntelliJ prompts to install the **Lombok plugin**, install and restart.

### 4. Set the JDK to 17
1. `File > Project Structure > Project`
2. Set **SDK** to a Java 17 JDK (add one via `Download JDK` if you don't have it).
3. Set **Language level** to 17.

### 5. Configure the API key as an environment variable (never hardcode it)
1. `Run > Edit Configurations...`
2. Add a new **Application** configuration:
   - Main class: `com.portfolio.qainference.QaInferenceServiceApplication`
   - Under **Environment variables**, add:
     ```
     GOOGLE_AI_API_KEY=<paste-your-real-key-here>
     ```
   - Optionally also set `GEMMA_MODEL_NAME` (defaults to `gemma-3-27b-it` if omitted — check
     https://ai.google.dev/gemini-api/docs/models for the exact Gemma model name currently
     available on Google AI Studio, since model names/availability change).
3. Apply and close.

   Alternative (recommended for teams): set `GOOGLE_AI_API_KEY` as a real OS-level environment
   variable, or copy `.env.example` to `.env` and use the [EnvFile IntelliJ plugin] to load it
   into the run configuration — either way, `.env` is already git-ignored.

### 6. Build the project
- `Build > Build Project` (or `mvn clean install` in the Maven tool window / terminal).
- Confirm it compiles with no errors.

### 7. Run the application
- Run the `QaInferenceServiceApplication` configuration (green ▶ button), or from terminal:
  ```bash
  mvn spring-boot:run
  ```
- Confirm the log shows Tomcat started on port 8080 and no Spring AI auto-config errors.

### 8. Verify Swagger / OpenAPI
- Open http://localhost:8080/swagger-ui.html
- You should see the `Chat` tag with `POST /api/v1/chat` documented.

### 9. Test the endpoint
```bash
curl -X POST http://localhost:8080/api/v1/chat \
  -H "Content-Type: application/json" \
  -d '{"prompt": "Based on the portfolio context below, summarize the investment performance: Portfolio returned 12% CAGR over 5 years with 8% volatility."}'
```
Expected response:
```json
{
  "response": "The portfolio has generated a CAGR of 12% over five years..."
}
```

### 10. Check health/metrics (Actuator)
- http://localhost:8080/actuator/health
- http://localhost:8080/actuator/metrics

### 11. Run the tests
- Right-click `src/test/java` > **Run 'All Tests'**, or:
  ```bash
  mvn test
  ```
- `AIChatServiceImplTest` mocks the Spring AI `ChatClient` (no real network call).
- `ChatControllerTest` uses `@WebMvcTest` + `MockMvc`, mocking the service layer.

## Design notes

- **Statelessness**: no session state, no in-memory conversation history — every request
  is self-contained, matching the "prompt already includes RAG context" contract.
- **Timeout handling**: `AIChatServiceImpl` submits the blocking Spring AI call to a
  virtual-thread executor and bounds it with `Future.get(timeout)`, converting a
  `TimeoutException` into a clean `504 Gateway Timeout` via `GlobalExceptionHandler`.
- **Layering**: Controller → Service → Spring AI `ChatClient`. The controller has zero
  business logic; the service has zero HTTP/Servlet imports (aside from the interface).
- **Config over code**: model name, temperature, max tokens, and timeout are all
  externalized to `application.yml` / env vars so ops can tune behavior without redeploying.
- **Secrets**: `GOOGLE_AI_API_KEY` is only ever read from the environment
  (`spring.ai.google.genai.api-key=${GOOGLE_AI_API_KEY}`). Nothing sensitive is committed;
  `.gitignore` excludes `.env` and any `application-local.yml`.

## Notes on the Gemma model name

Google AI Studio serves both Gemini and Gemma family models through the same Google GenAI
endpoint. Model identifiers occasionally change as new versions ship — before deploying,
check https://ai.google.dev/gemini-api/docs/models for the current Gemma model ID and update
the `GEMMA_MODEL_NAME` environment variable accordingly; no code change is needed.
